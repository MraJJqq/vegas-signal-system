# VEGAS V9 规则说明

## 核心信号规则（继承 V8，不擅自改动）
- 扫描周期：1H，只使用已收盘的 K 线确认。
- 观察线：中锋 EMA144、EMA169；红峰 EMA576、EMA676。
- 当 K 线高低区间覆盖任一观察线时，进入观察状态并记录触及线及时间。
- 观察状态持续期间，收盘价高于 EMA12，产生“上方”正式信号；低于 EMA12，产生“下方”正式信号。
- 收盘价等于 EMA12 时不确认，保持观察状态。
- 确认后退出观察状态；通过持久化状态避免重复处理旧 K 线。
- 仅纳入中国时区当天的正式信号；数据错误或无可用已收盘 K 线的品种排除本轮扫描。
- 数据源：Bitget USDT 永续合约；沿用 V8 的品种池和指标计算方式。

## 通知规则
- 每小时扫描一次，支持 GitHub Actions 手动触发。
- 每轮扫描只筛选 formal_signal 为 true 的记录；不做“新增信号”比较，符合条件的信号每轮都会通知。
- 没有正式信号时不发送通知。
- 同一条通知内按品种去重，并按固定品种顺序排序。
- 同时发送 ntfy 与 Bark；任一通道失败则任务失败。HTTP 2xx 只代表服务端接受请求，不保证手机最终展示。
- 需要配置 GitHub Secrets：V8_NTFY_TOPIC、可选 V8_NTFY_TOKEN、V8_BARK_KEY（V9 工作流使用对应的 V9 前缀 secrets）。

## 通知排版规则
- 标题：VEGAS V9 SIGNAL SYSTEM。
- 分组标题：美股巨头、核心能源。
- 品种格式：▰ SYMBOL ▰。
- 美股每行最多三个品种；核心品种同组排列。
- 核心品种顺序：BTC、HYPE、XAU、CL、SNDK。
- 美股按 V8 已有固定顺序排列；未知品种追加在已知品种之后。
- Bark 标题独立显示，正文不重复系统标题；测试推送需加测试标记。

## 隔离与验证
- V9 文件独立放在 v9/，V8 目录和 V8 工作流保持不变。
- V9 使用独立信号状态文件与报告文件。
- 修改后应通过 Python 编译、单元测试，并手动运行一次工作流检查通知链路。
