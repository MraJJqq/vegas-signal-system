# VEGAS V9 规则说明

## 核心信号规则（继承 V8，不擅自改动）
- **观察期：** 使用已收盘的 4H K 线；当高低区间触及中锋 EMA144/169 或红峰 EMA576/676 时进入观察期。观察期不限时，价格离开均线区域也不取消。
- **信号期：** 观察期由已收盘的 4H K 线确认后，等待之后收盘的 1H K 线；无论触发中锋还是红峰，统一比较该 1H 收盘价与 1H EMA12。收盘价在 EMA12 上方或下方均产生一次正式信号，不判断方向；等于 EMA12 不确认。
- 每轮观察期最多产生一次正式信号；信号推送后结束本轮观察，等待下一次 4H 触碰。
- 4H 负责观察期触发，1H EMA12 负责信号期确认；两者严格分开。程序按 K 线收盘时间顺序处理事件，避免把触碰前的 1H K 线用于确认，也避免同一轮观察期间遗漏信号后的新触碰。
- 收盘价等于 EMA12 时不确认，保持观察状态。
- 确认后退出观察状态；通过持久化状态避免重复处理旧 K 线。
- 仅纳入中国时区当天的正式信号；数据错误或无可用已收盘 K 线的品种排除本轮扫描。
- 固定扫描池共 27 个：核心能源 4 个（BTC、HYPE、XAU、CL），以及美股巨头/科技股 23 个（AAPL、MSFT、GOOGL、AMZN、NVDA、TSLA、META、INTC、QCOM、AMD、TSM、AVGO、ORCL、ARM、MU、ASML、SNDK、SKHYNIX、MRVL、GLW、HOOD、CBRS、SPCX）。
- 不再按 24 小时成交额筛选；上述 27 个品种全部进入每轮扫描。仅当某品种行情数据不可用或错误时，才标记为本轮数据异常。
- 数据源：Bitget USDT 永续合约；沿用 V8 的指标计算方式。

## 通知规则
- 每小时扫描一次，支持 GitHub Actions 手动触发。
- 每轮扫描推送当天累计的全部正式信号，不只推送新增信号。
- 当天没有任何正式信号时，仍发送 Bark 通知；“美股巨头”和“核心能源”两个分类均显示 `▰ No change ▰`。
- 同一条通知内按品种去重，并按固定品种顺序排序。
- **只使用 Bark 推送；不使用 ntfy。** Bark 失败则任务失败。HTTP 2xx 只代表服务端接受请求，不保证手机最终展示。
- 只需配置 GitHub Secret：V9_BARK_KEY。

## 通知排版规则
- 标题：VEGAS V9 SIGNAL SYSTEM。
- 分组标题：美股巨头、核心能源。
- 品种格式：▰ SYMBOL ▰。
- 美股每行最多三个品种；核心品种同组排列。
- 核心品种顺序：BTC、HYPE、XAU、CL。
- 美股按已确认的 23 个候选品种顺序排列；通知分类标题仍为“美股巨头”，核心品种仍单独显示在“核心能源”下。
- Bark 标题独立显示；正文不重复系统标题；测试推送需加测试标记。

## 隔离与验证
- V9 文件独立放在 v9/，V8 目录和 V8 工作流保持不变。
- V9 使用独立信号状态文件与报告文件。
- 修改后应通过 Python 编译、单元测试，并手动运行一次工作流检查 Bark 通知链路。
